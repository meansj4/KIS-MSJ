# 전체 BUY 부족금액 기반 LOT 교체 (2026-10-14)

운영의 `cash_shortfall_rotation_enabled=true`를 그대로 사용한다. 별도 활성화 flag는 없다. 이전의 단일 매수 종목 자금 예약 방식은 이 방식으로 대체한다.

## 총 필요금액과 회수액

전체 종목을 조회해 현금 이외의 계좌·종목·매수 정책을 통과한 BUY 가격 신호를 수집한다. 후보마다 최종 수량×지정가의 필요금액을 기록한다. 후보의 가격과 조건을 다시 조회해 주문금액을 갱신하고, 가격조건이 사라졌거나 매수 차단·검토·동기화·거래소 조건에 걸린 후보는 제외한다. 신규 후보는 전체 조회에서 추가한다.

대기 목록은 `cash_rotation_plan`의 `targets`에 저장한다. 특정 종목이 회수 현금을 독점하지 않는다. 회수 현금으로 실행 가능한 BUY는 기존 순서대로 가격 안정성과 최종 위험 조건을 다시 확인해 실행한다. 비싼 BUY가 현금으로 살 수 있는 다른 BUY를 막지 않는다. 실제 BUY 체결분은 대기 목록과 원장의 필요금액에 반영한다. 원금/LOT 한도, 쿨다운과 런타임 차단은 유지한다.

`추가 회수 필요금액 = max(0, 대기 BUY 총액 - max(실제 주문가능현금, 시작현금 + 교체 순회수액 - 이후 실제 BUY 지출))`

총액이 최소 현금 기준보다 작은 경우 기존 매수 전 최소 현금 기준까지 회수한다. 순회수액은 실제 체결수량×체결가에서 설정의 추정 매도비용을 차감한다. 이미 체결됐지만 증권사 현금에 반영되지 않은 돈은 추가 청산을 막는 데만 사용하고, BUY에는 실제 주문가능금액만 사용한다. 실제 현금은 새 계좌 조회로 확인한다. 같은 돈을 여러 주문에 배정하지 않으며 부분체결/취소거절/접수결과 불명 주문이 있으면 확인을 기다린다.

## 여러 오래된 LOT 정리

계좌의 매도 가능한 OPEN LOT을 실제 매수 체결시각 기준 오래된 순서로 정리한다. 총 부족금액을 채우기 위해 필요한 만큼 여러 LOT을 순차 처리한다. 앞 LOT 전체를 팔아도 부족하면 다음 LOT으로 진행하고, 마지막 LOT은 필요한 정수 수량까지만 정리한다.

가격은 `order.sell_limit_markdown_pct`를 적용한다. 현재 운영 값인 **0.5**는 해당 거래소의 최신 현재가 대비 **−0.5% 지정가**다. 시장가로 바꾸지 않는다. 가격과 회수액에는 호가단위를 반영한다. 지정가는 그 가격 이상에서 체결될 수 있고 체결을 보장하지 않는다.

미체결 취소가 확정된 LOT은 같은 처리 주기에서 다시 붙잡지 않고 다음 오래된 LOT으로 진행한다. 미확정 상태에서는 다음 주문을 제출하지 않는다. 실제 체결 뒤 총 부족금액과 현금을 재계산하고, 가능한 BUY를 실행한다. 총액을 전부 모을 때까지 기다리지 않는다.

대기 BUY 종목은 즉시 같은 종목을 사고파는 충돌을 피하기 위해 교체 매도에서 제외한다. 설정 밖/비활성/수동전용/거래위험/수량 동기화 불일치 종목도 제외한다. 기존 buy_blocked/retire_after_exit 종목은 매도가 허용되면 대상이 될 수 있다.

## 교체 매도 후 새 매수 가격

교체 매도 전용60분 재매수 차단은 사용하지 않는다. 마지막 교체 매도 주문의 실제 체결가(VWAP)를 기준으로 새 매수 가격 구간을 확인한다. 잔여 LOT이 있는 경우 현재 LOT 구간의 기존 추가매수 하락률을 사용한다. 예를 들어 체결가10,000원, 기존 매수 간격4%라면9,600원 이하이면서 기존 BUY 신호도 충족해야 재매수할 수 있다. 시간이 한 시간 지나도 같은 가격은 허용되지 않고, 한 시간 전이라도 새 가격 조건에 도달하면 허용된다. 수량 감소나 LOT 구간 변경만으로 같은 가격의 BUY를 다시 실행하지 않는다.

전량 매도한 경우 기존 재진입 하락률을 적용하며, 실제 새 고점과 기존 추적 재진입 조건을 충족한 새 파동도 허용한다. 기존 재진입 최소 대기·BUY 체결 쿨다운·위험/수량/런타임 조건은 그대로 검사한다. BUY 지정가도 새 가격 상한 이하로 제한해 오래된 매수 목표가나 매수 가산율 때문에 높은 가격에 재매수하지 않는다. 호가 상한은 내림 처리한다.

실제 BUY가 체결되면 해당 교체 매도 기준은 소진되고 기존 전략으로 돌아간다. 다시 교체 매도되면 새 체결가를 기준으로 재설정한다. 기준은 체결 원장에서 재구성하므로 재시작·부분체결·지연된 과거 체결 수입에도 유지된다. 새 차단 사유는 `cash_rotation_wait_new_buy_price`다. 기존 설정의 `cash_shortfall_rotation_buy_cooldown_minutes`는 저장 파일 호환을 위해 남겨두지만 거래 판단에는 사용하지 않고 UI 시간 설정에서도 제거한다. 새 flag는 필요 없다.

## 처리 주기와 안전장치

루프당 교체1건 제한은 제거한다. 교체 처리에서는 약60초의 주문 처리 구간 안에서 여러 LOT을 처리하고, 미체결 주문의 기존 timeout은 유지한다. 60초는 주문 수 제한이 아니라 일시정지와 다른 작업의 응답성을 위한 처리 시간 한도이며 API 조회/진행 중 주문 대기는 이를 넘길 수 있다. 다음 루프에서 이어서 처리한다.

대기 목록이 있으면 전체299종목 순회를 반복하기 전에 대기 후보를 갱신하고 교체를 진행하는 경로를 사용한다. 약5분 간격으로 전체 종목 조회를 다시 수행해 신규 후보와 기존 정상 SELL을 확인한다. 조회/API 지연 때문에 실제 간격은 더 길 수 있다. 전체 후보 수집 단계에서는 곧바로 실행하지 않을 BUY의 반복 가격 샘플을 생략하고, 실제 BUY/교체 SELL 직전 샘플 검사와 세션 확인은 유지한다.

2026-10-14 처리 속도 보완: 전체 종목 스캔 중에도 약30초의 스캔 구간마다 기존 대기 수요와 새로 발견한 수요를 합쳐 교체 처리를 실행한다. 아직 스캔하지 않은 종목의 대기 수요를 지우지 않고, 전체 스캔 완료 시 목록을 교체한다. 따라서 전체 스캔 완료까지 몇 분간 교체 매도가 쉬는 구간을 줄인다. 교체 처리 시작 시 전체 대기 후보를 재검증하고, 매도 처리 도중30초마다 하는 갱신은 후보5개씩 순환한다. 중간 전체 재조회가60초의 매도 처리 시간을 소모하는 문제를 방지한다. `cash_rotation_tick_end`에 발주 시도 수, 잔여 부족금액, 소요시간, 중단 및 후보 제외 사유를 기록한다.
