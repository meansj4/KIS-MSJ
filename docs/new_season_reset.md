# 신규 시즌 전환

신규 시즌은 기존 DB를 지우는 단축기능이 아니라 백업, 실제 잔고 확인, 청산계획, 주문요청, 잔고 0 확인, 초기화 순서의 보호된 작업이다. UI의 New Season 탭이 이 절차를 안내한다.

## 안전 순서

1. 봇을 안전하게 pause하고 중복 프로세스와 미체결 주문을 확인한다.
2. 설정·DB·로그 아카이브를 생성한다.
3. KIS 잔고 스냅샷을 생성하거나 업로드하고 유효시간과 계좌 일치를 검증한다.
4. 청산계획을 dry-run으로 만든다.
5. 확인문구 후 `manual_order_requests`에 청산 요청을 생성한다.
6. 봇이 요청을 처리한 뒤 KIS 실제 잔고와 미체결을 다시 확인한다.
7. 잔고·미체결·처리중 수동요청이 모두 안전할 때만 DB reset을 실행한다.

UI는 직접 KIS 주문을 발사하지 않는다. 수동요청 큐를 통해 봇이 동일한 주문·체결 정합성 경로를 사용한다.

CLI 보조도구:

```powershell
.\.venv\Scripts\python.exe scripts\prepare_new_season.py --help
```

reset 전 백업 없이 진행하거나, 실제 잔고가 남은 상태에서 DB만 초기화하면 LOT/계좌 불일치가 발생한다. 이전 시즌 DB는 분석과 감사 목적으로 보존한다.
