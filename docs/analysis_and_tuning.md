# 분석과 전략 튜닝

## 데이터 추출

```powershell
.\.venv\Scripts\python.exe scripts\export_analysis_dataset.py --help
```

UI 포트폴리오 그래프도 JSON/CSV로 내보낼 수 있다. 외부 분석에는 JSON이 지표 정의와 데이터 한계를 함께 담으므로 우선 권장된다.

## 평가 단위

전략 평가는 단순 실현손익보다 다음을 함께 본다.

- 실제 계좌 총자산의 시작일 대비 변화
- 같은 기간 KOSPI 또는 적절한 벤치마크 대비 성과
- 실현손익과 미실현손익의 합
- 매도사유별 횟수·금액·순손익
- +목표수익 회전이 deep-loss recovery 손실을 감당하는지
- 현금비중, 종목·테마 집중도, 매수차단·검토상태의 자금 묶임
- 최대 낙폭과 회복기간

짧은 일방향 하락장만으로 횡보장 회전전략을 확정 평가하기 어렵다. 다만 손실 비대칭, 과도한 물타기, 잦은 검토차단은 기간이 짧아도 즉시 점검할 위험신호다.

## 데이터 한계

DB는 자동매매 LOT과 체결을 중심으로 기록한다. 과거 모든 날짜의 실제 예수금·총평가·입출금 원장은 아니다. 따라서 `총투입금액 + 현재 예수금`이나 재구성 그래프를 증권사 총자산과 그대로 비교하면 오차가 생긴다. 기준일 비교는 KIS 실제 계좌 스냅샷과 입출금·배당 내역을 별도로 확보해야 한다.

## 튜닝 원칙

한 번에 한 축만 바꾸고 변경일·설정·가설을 기록한다. 목표수익, 추가매수 간격, recovery, 종목 수를 동시에 바꾸면 원인분리가 불가능하다. 비용은 현재 0.21% 추정치를 사용하되 실제 계좌 체결명세로 주기적으로 보정한다.
