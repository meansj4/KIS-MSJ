## 실행 시 동작

1. 같은 운영 DB를 사용하는 봇의 중복 실행을 OS 잠금으로 차단한다. 잠금은 DB를 열기 전에 획득하고 종료·비정상 종료 시 해제된다.
2. 실계좌 연결과 실제 체결 이력을 조회하고, 잔고·LOT 수량·미체결 주문·대기 수동요청을 확인한다. 누락 체결을 주문 지정가로 추정하는 보정이나 주문 취소는 사전 점검에서 실행하지 않는다.
3. 완료된 수정종가로 변동성을 준비하고 실제 종목별 시세로 매수 상한·LOT별 매도 목표를 계산한다. 데이터 부족 기본값은 기존 명세대로 허용하며 조회 실패는 시작을 차단한다.
4. 점검 성공 및 설정·운영 정지 파일의 변경 없음이 확인되면 준비 작업용 정지만 해제하고 동일 봇 객체로 매매 루프에 진입한다. 이후 사용자가 UI에서 설정한 정지는 자동으로 덮어쓰지 않는다.
5. 장외에는 기존 거래 시간 규칙에 따라 대기하고, 매매 시점마다 최신 주문·잔고·가격·위험 제한을 다시 확인한다.

직접 실행: `run_live_ready.cmd`. 주문 없이 재점검: `.venv/Scripts/python.exe scripts/run_live_ready.py --check-only`.

일반 `python main.py --config config/lot_auto_trader.json` 명령은 저장된 정지 상태를 그대로 사용한다. 자동 준비 해제까지 포함한 실행은 `run_live_ready.cmd`를 사용한다.

## 운영 준비

운영 DB 초기화 시 SQLite 온라인 백업 후 새 상태 열과 체결 고유 제약을 업그레이드한다. 보유 LOT·체결 ID·귀속 자료는 보존하며 실제 체결금액과 소수 평균가도 보존한다. 준비 중에는 전체 주문 정지를 유지한다.

`readiness.py`는 증권사 요청을 GET으로 제한하고 주문·취소 메서드도 차단한다. 인증 토큰 발급은 연결에 필요한 인증 작업이다. `run_once`와 주문 취소를 포함하는 `reconcile_open_orders`는 사전 점검에서 호출하지 않는다.

신규 최초매수 이름 `adaptive_initial_buy`에도 기존 활성 종목 수·일일 신규 주문 수·일일 신규 금액 제한과 화면 집계를 적용하도록 보완했다. 미처리 수동 주문이 남아 있으면 자동으로 실행하거나 삭제하지 않고 시작을 보류한다.
