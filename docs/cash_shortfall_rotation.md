# 현금 부족 시 오래된 LOT 교체

> 아래는 2026-10-13 최초 구현의 기록이다. 2026-10-14부터 단일 대상 예약과 현재가 교체 매도는 [전체 BUY 부족금액 및 −0.5% 교체 정책](cash_rotation_aggregate.md)으로 대체됐다.

`risk.cash_shortfall_rotation_enabled=true`이면 가격 신호와 기존 계좌·종목·런타임 제한을 통과한 BUY가 현금 부족으로 실행되지 못할 때 자금을 회수한다. 일반 라이브러리 기본값은 false이며 운영 JSON에서 선택한다. 계좌 손실 제한·매수차단·검토·동기화·거래정지 등을 무시하지 않는다.

## 실행 순서

1. 최초/추가/일반·trailing·timeout 재진입의 BUY 신호를 실제 현금 검사와 분리한다. 최종 수량×지정가와 기존 최소 매수 전 현금 기준을 충족하는 데 필요한 금액을 계산한다.
2. 실거래에서는 계좌 잔고·주문가능금액을 새로 조회한다. API 오류·미체결·부분체결·접수결과 불명 주문이 있으면 추가 정리와 BUY를 보류한다.
3. 다른 종목의 OPEN LOT을 실제 매수 체결시각 기준으로 오래된 순서로 선택한다. 설정 밖/비활성/수동전용/거래위험/동기화 불일치 종목은 제외한다. buy_blocked·retire_after_exit 종목은 매도가 가능하면 정리 대상에 포함한다. 손실 여부로 제외하지 않는다. 매수 대상과 같은 종목은 즉시 재매수 충돌을 피하기 위해 제외한다.
4. 해당 LOT의 잔여수량과 부족분을 충당할 정수수량 중 작은 값만 매도한다. 가격은 주문 직전 해당 거래소에서 확인한 **현재가 지정가**다. 기존 0.5% 매도 markdown을 적용하지 않으며 시장가로 전환하지 않는다. 샘플 변동성이 크거나 거래소의 시세·세션 조건이 유효하지 않으면 주문하지 않는다.
5. 한 루프에서 교체 SELL은 최대 하나다. 정상 30초 주문 timeout·취소·체결 재조회 절차로 처리한다. 다음 루프는 자금 확보 중인 BUY 종목부터 재평가한다.
6. 실제 매도 체결수량만 원가·잔량·실현손익에 반영한다. 매도 예상대금만으로 BUY하지 않는다. 증권사의 주문가능금액에 반영되고 BUY 가격조건이 여전히 유효할 때 BUY한다. 신호가 사라지면 추가 교체를 멈추고 현금을 유지한다.

## 영속 상태와 중복 방지

`cash_rotation_plan` 단일 행에 목적 BUY 종목·시작 현금·체결 원장 watermark를 저장한다. 한 후보에 자금을 배정하는 동안 다른 자동/수동 BUY는 같은 자금을 사용할 수 없다. 기존 정상 SELL은 유지한다.

이미 매도해 회수한 비용 후 금액을 원장에서 계산한다. 시작 현금+기회수액이 필요한 금액을 충족했는데 실제 주문가능금액이 아직 부족하면 반영을 기다린다. 같은 부족분 때문에 추가 LOT을 계속 팔지 않는다. 이 상태는 봇 재시작에도 유지한다. 외부 입출금이나 증권사 현금 제한이 생기면 기다림이 길어질 수 있으며, 가용금액이 확인되지 않은 상태에서 추가 청산으로 이를 메우지 않는다.

실거래 신규 주문은 발주 전 INTENT를 저장한다. 접수결과가 불명확하면 자동 재발주하지 않고 미확인 상태를 보존한다. 증권사 주문번호와 로컬 주문 식별자를 분리해 날짜·종목·방향·거래소를 포함한 식별자로 기록한다. 취소에는 원래 증권사 번호를 사용한다. HTTP 계층에서도 결과 불명 POST를 자동 재시도하지 않는다. 명시적 거절은 REJECTED로 기록한다.

매도 사유는 `CASH_SHORTFALL_ROTATION`이다. 기존 수익매도와 구분해 LOT·체결 이력에서 확인한다. `risk.cash_shortfall_rotation_buy_cooldown_minutes`는 기본 60분이며 교체 매도한 종목의 모든 BUY를 그 기간 차단한다. 전량 정리 후에는 기존 WAIT_REENTRY/retire_after_exit 상태 전이를 적용하며, LOT 매수시각이나 누적 age decay는 초기화하지 않는다.

## 설정과 적용

```json
{
  "risk": {
    "cash_shortfall_rotation_enabled": true,
    "cash_shortfall_rotation_buy_cooldown_minutes": 60
  }
}
```

코드 변경은 Python 프로세스 재시작이 필요하다. config reload만으로 새 코드가 반영되지는 않는다. 운영 설정 변경은 백업·원자 저장·검증 경로를 사용한다. 모의검증은 임시 DB와 가짜 증권사만 사용하며 실계좌 시험 주문을 제출하지 않는다.

## 검증 범위

오래된 손실 LOT 우선·필요수량만 매도·현재가/시장가 미사용·실체결 후 BUY·현금 이외 위험조건 유지·신호 소멸·부분체결·미체결 취소·재시작 후 반영 대기·재매수 쿨다운·다른 BUY의 자금 사용 차단·보호 종목 제외·shadow 무변경·일반장 주문 intent/취소/체결 식별자·HTTP 중복 POST 방지를 테스트한다.

자본 회전 기능을 구현한 것이며 수익 개선을 입증한 백테스트는 아니다. 교체 손실·거래비용과 새 매수 이후의 평가손익을 함께 평가해야 한다. 자금이 충분한 BUY에서는 교체 매도가 발생하지 않는다.
