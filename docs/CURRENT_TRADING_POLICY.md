# 현재 전체 거래 정책 — Adaptive LOT V2

작성 기준: 2026-10-26의 예수금 배율·완료 LOT 추세 수정 소스. 이 문서 하나로 독립 검토할 수 있도록 수식, 상태, 주문 경계를 함께 기술한다. **코드 수정과 실제 실행 중인 프로세스의 적용은 별개다. 이번 작업에서 봇을 재시작하거나 운영 DB·설정·일시정지를 변경하지 않았고 증권사 주문도 실행하지 않았다.** 새 소스는 다음 프로세스 시작에 사용된다. 기존 프로세스는 편집 전 모듈을 계속 사용할 수 있다. 현금별 동작과 재현법은 [예수금 시나리오](ADAPTIVE_CASH_SCENARIOS.md), 직접 조건을 바꿔 보는 도구는 [오프라인 계산기](ADAPTIVE_CASH_SCENARIOS.html)를 참조한다.

## 1. 전략의 범위와 데이터

운영 설정 `strategy.adaptive_lot_enabled=true`일 때 아래 정책을 사용한다. 종목별 여러 매수 주문을 LOT으로 보관하며, 추가매수는 종목 전체 평가손익률, 매도는 개별 LOT 원가를 기준으로 한다. 자동 종목 발굴 전략이 아니라 설정된 종목 목록과 enabled/manual_only/buy_blocked/danger/retire 상태를 사용하는 실행 전략이다. 신규 종목·중지 종목은 별도 설정과 위험 검사를 통과해야 한다.

가격·잔고·주문가능 현금·실제 체결은 KIS 조회가 근거다. 계좌와 LOT 수량 불일치는 동기화 문제이며 평균단가를 임의로 맞춰 매수하지 않는다. 화면의 종목 평균단가와 손익률은 LOT 잔여 수량 및 원가에서 계산한다. 증권사의 평가손익률은 수수료·세금·단가 반올림·조회시각이 다를 수 있다. **추가매수에는 수수료·세금 제외 가격 손익률을 사용하며, 증권사 화면 손익률을 수식에 대입하지 않는다.** 실계좌와의 수치 일치 검증은 이번에 실행하지 않았다.

구현: `strategy.LotGridStrategy.decide/_adaptive_decide`, `position_manager.PositionManager.refresh_from_lots`, `kis_client.KisClient`, `risk_manager.RiskManager`.

## 2. 시간과 실제 거래일

`trading_calendar.TradingCalendar`는 KST로 시간을 통일하고 KIS `GET /uapi/domestic-stock/v1/quotations/chk-holiday`, `CTCA0903R`의 `bass_dt`, `opnd_yn`을 사용한다. 평일이라는 이유만으로 거래일이라고 추정하지 않는다. 자료는 운영 DB와 별도인 `<DB이름>.krx_calendar.json`에 새 프로세스 실행 중 캐시된다. 이번 작업에서 이 운영 캐시를 생성하거나 조회 API를 실행하지 않았다.

추세 창은 거래일 장중·장전·시간외에 당일과 직전 4거래일, 휴장일에는 최근 5개 거래일이다. 체결 시각을 KST 거래일에 귀속한다. 미래 시각의 체결은 포함하지 않는다. 거래일 자료가 없거나 조회가 실패하면 `krx_calendar_*` 원인으로 새 자동 매매 판단을 보류한다. 체결 반영은 계속한다. 누락 캘린더를 임의의 0점이나 달력일 계산으로 대체하지 않는다.

완료 세션의 기본 경계는 현재 설정 `market_hours.close_time`(15:30)이다. **수능일 등 정규장 종료시각이 다른 날은 해당 종료시각에 맞는 설정이 필요하다. 현재 휴장일 API만으로 날짜별 특수 종료시각까지 복원하지 않는다.** 이 경계는 실시간 운영 검증이 아직 필요하다.

공식 요청 예제: [한국투자증권 국내휴장일조회](https://github.com/koreainvestment/open-trading-api/tree/main/examples_llm/domestic_stock/chk_holiday). 거래소 일정 참고: [KRX 휴장일](https://open.krx.co.kr/contents/MKD/01/0110/01100305/MKD01100305.jsp).

## 3. 변동성 배율 — 유지

종목별 완료된 수정종가 61개로 로그수익률 60개를 만든다. 최근 20개 및 60개의 표본 표준편차(ddof=1)에 `sqrt(252)*100`을 곱해 연환산 변동성 **퍼센트**를 얻는다.

```text
r[t] = log(C[t]) - log(C[t-1])
vol20 = stdev(r[-20:]) * sqrt(252) * 100
vol60 = stdev(r[-60:]) * sqrt(252) * 100
V = 0.3*vol20 + 0.7*vol60
m = clamp(4*(V/18.41)^0.3707491793, 3, 10) / 4
```

`m`은 무차원, 0.75~2.5다. V=18.41이면 m=1. 이 clamp는 변동성 단계만 제한하며 최종 손실 기준을 3~10%로 제한하지 않는다. 데이터 부족·불량이면 기존 정책대로 m=1이다. `volatility.calculate_volatility/DailyVolatilityCache`, `main.refresh_daily_volatility`, `kis_client.adjusted_daily_closes`에서 계산·조회·일별 캐시한다. 수정주가는 `FID_ORG_ADJ_PRC=0`, 원주가는 1이다. 장중에는 완료 일봉 기준 캐시를 사용하며 매 루프에 변동성을 다시 계산하지 않는다.

## 4. 최근 5거래일 완료 LOT 순점수 — 2026-10-26 정정

**주문 수나 부분체결 수를 추세에 사용하지 않는다.** 매수는 원래 주문수량 전부가 체결되어 완성된 LOT당 +1, 매도는 LOT 잔여수량이 0이 되어 전량 매도된 LOT당 -1이다. 매수·매도 완료는 각각 LOT별 한 번만 집계하며, 완료된 시각의 KST 거래일에 귀속한다. 부분매수 중이거나 일부 수량만 매도된 LOT은 해당 방향의 점수가 없다. 매수 주문수량을 모르면 완료를 추정하지 않는다. 일부 체결 뒤 나머지가 취소된 매수도 완전 매수 LOT으로 세지 않는다.

예: 10주 LOT을 2주씩 다섯 주문으로 팔아도 앞의 네 번은 0, 마지막 2주 매도에서만 -1이다. 하나의 매도 체결이 두 LOT을 완전히 닫았다면 LOT별 -1로 합계 -2다. 같은 LOT을 같은 창에서 완전 매수하고 전량 매도하면 +1과 -1이 상쇄된다. 정상 수익실현·Decay·손실회복 등 매도 유형은 완료 LOT 집계에 영향을 주지 않는다. 부분매도도 최신 매도가와 재진입 제한에는 기존대로 반영한다.

완료 여부를 적용하는 대상은 추세다. 실제 보유 중인 부분매수·부분매도 LOT은 기존대로 잔고·위험 한도·현재 LOT 수 N·Decay 계산에 포함한다. 금액 예산을 한 푼도 남김없이 쓰는 뜻이 아니라, 호가·정수 수량으로 산출된 원 매수 주문수량의 전량 체결이 매수 완료 기준이다.

```text
raw_score = 최근 5거래일 완전 매수 LOT 수 - 전량 매도 LOT 수
s = clamp(raw_score, -12, +12)
t_buy  = 1 + 0.2*max(0, s-1)
t_sell = 1 + 0.2*max(0,-s-1)
```

예: 완료 LOT 이벤트 BUY, BUY, BUY, SELL, BUY, BUY는 s=+4, t_buy=1.6, t_sell=1.0이다. s=-4이면 1.0/1.6, s=±12이면 해당 방향 3.2다. 매도 후 하락 재매수 조건에는 이 배율을 적용하지 않는다.

`fill_state.record_actual_fill_state`가 기존 `actual_fill_events` JSON에 `kind=LOT_COMPLETE`, LOT ID, 방향, 완료 시각을 기록한다. `trading_calendar.completed_lot_counts/trend_score`, `LotManager.trend_score_for`는 이 완료 증거만 사용하고 과거 주문 이벤트는 추세에서 제외한다. 새 DB 열은 없다. `TradeFill.order_quantity`는 주문 매칭·누적 체결 차분·재조정 경로에서 원 요청수량을 전달한다. 단순 접수나 상태 문자열만으로 완료를 인정하지 않는다.

복원된 미완료 LOT의 마지막 귀속 체결시각은 `LOT_PROGRESS` 보조 증거로 보존하며 추세 점수나 주문 기준 호환 횟수에는 넣지 않는다. 나중에 오래된 체결이 지연 도착하여 LOT이 닫혀도 마지막 실제 체결일을 완료일로 유지하기 위한 정보다.

기존 장부는 `lot_completion.read_completion_history/reconstruct_completions`에서 LOT·원주문·체결·LOT 귀속을 읽기 전용으로 대조해 복원한다. 원 요청수량과 매수 체결 합계 및 LOT 매수수량이 일치해야 BUY 완료, LOT이 CLOSED/잔여 0이며 귀속 매도수량 합계가 LOT 전체수량과 일치해야 SELL 완료다. 귀속·수량이 불명확하면 누락을 주문 수로 대체하지 않는다. 닫힌 과거 LOT도 포함하고 부분체결의 마지막 기록 시각을 완료 시각으로 사용한다. 브로커가 실제 하위 체결 시각을 제공하지 않은 누적 체결 자료의 시각 정확도는 기존 기록의 한계가 남는다.

복원은 시작 시와 최종 주문 가드의 `StateStore.load_positions`, 읽기 전용 UI의 캐시된 `positions` 경로에 공통 적용된다. 원본 읽기만으로 운영 DB를 덮어쓰지 않으며, 다음 정상 봇 실행의 일반 상태 저장은 완료 이력을 보존한다. 오래된 완료는 창에서 제외할 뿐 삭제하지 않는다. 기존 `consecutive_buy_count/consecutive_sell_count`는 주문 기준 호환 이력이며 추세 계산에는 사용하지 않는다. 실행 로그와 전략 컨텍스트에는 완료 BUY/SELL LOT 수와 점수를 별도로 표시한다.

주문 식별자는 기존의 KST 날짜·종목·방향·정규화 주문번호를 사용한다. 증권사 번호의 다음 날 재사용은 다른 주문이다. 서로 다른 날짜에 걸친 동일 주문의 부분 체결을 일괄 식별할 생성일 정보가 없는 경우 이 기존 식별 정책의 한계가 남는다. KIS가 하위 체결 대신 누적 평균가만 제공하면 마지막 하위 체결 하나의 정확한 시각·가격을 새로 복원할 수 없다.

## 4.1. 주문가능현금 배율 — 2026-10-26 추가

`C=AccountSnapshot.cash_available`인 증권사 주문가능현금을 사용한다. 총 평가자산이나 아직 체결되지 않은 매도대금으로 대체하지 않는다. 브로커에 반영된 예약금을 다시 차감하지 않는다. 아래 세 기준점은 한 직선에 놓이지 않으므로 0~1억 원, 1억~2억 원을 각각 선형으로 연결한다.

| 주문가능현금 | 매수 하락폭 배율 b | 매도 목표 배율 c |
|---:|---:|---:|
|0원|2|0.5|
|5천만 원|1.5|0.75|
|1억 원|1|1|
|1억 5천만 원|0.75|1.5|
|2억 원 이상|0.5|2|

```text
x = min(C, 200,000,000) / 100,000,000
0 <= x <= 1: b = 2-x,           c = 0.5+0.5*x
1 <  x <= 2: b = 1-0.5*(x-1), c = x
```

2억 원 초과는 끝점 배율을 유지한다. 미확인·음수·NaN·무한대·불리언 현금은 0원으로 대체하지 않고 `adaptive_cash_snapshot_unavailable`로 자동 매수·매도 판단을 보류한다. 실제 0원은 유효한 값으로 매도 목표를 0.5배 조정하지만, 매수에는 별도 현금·최소현금 검사가 적용된다.

변동성과 추세를 먼저 반영한 뒤 매수 하락폭과 매도 기본 목표에 각각 b와 c를 곱한다. 매도에서는 그 다음 Decay를 마지막에 차감하며 Decay 자체에 예수금 배율을 곱하지 않는다. 재진입 하락폭에도 b를 곱하되 기존대로 추세는 넣지 않는다. 최초 0LOT 진입에는 가상의 하락폭을 만들지 않는다. 아래 별도 명시 없는 수치 예시는 현금 1억 원, b=c=1을 가정한다.

구현: `adaptive_policy.cash_multipliers`, `strategy.adaptive_buy_details/_adaptive_sell_candidate`, `lot_manager.current_target_profit_info/update_lot_target_metadata`. Adaptive 활성 시 적용하며 과거 `cash_target_profit_enabled/cash_buy_drop_enabled` 정책을 다시 켜는 것이 아니다. 기존 예비금·손실회복·위험 한도는 유지한다. DB 스키마와 런타임 설정을 변경하지 않는다.

체결 반영은 현금 조회 없이도 보존해야 하므로 현금 없는 LOT 생성·메타데이터 계산은 미보정 임시값을 만들 수 있다. 이 값으로 자동 주문을 허용하지 않는다. 실제 판단은 유효한 현금을 명시해 목표를 다시 계산하고, 제출 직전 BUY 가드도 최신 현금으로 가격을 재검사한다. 화면은 최근 로그 현금을 사용하며 미확인·오래된 현금이면 목표를 확정 표시하지 않는다. 기존 접수 주문을 이 변경만으로 자동 취소·정정하지 않는다.

## 5. 최초 진입·추가매수·매도 후 재매수

### 평가PnL 기준

보유 LOT의 잔여 수량을 q[i], 개별 체결 원가를 p[i]라 하면 다음과 같다. 실현손익은 분모·분자에 넣지 않는다.

```text
Q = sum(q[i])
VWAP = sum(p[i]*q[i]) / Q
position_pnl_pct = (현재가/VWAP - 1)*100
N = 현재 잔여 수량이 있는 LOT 수
base_threshold_pct = -(4 + 2*(N-1))
effective_threshold_pct = base_threshold_pct * m * t_buy * b
pnl_target = VWAP * (1 + effective_threshold_pct/100)
```

| 현재 LOT 수 N | 기본 기준(%) | 다음 검토 |
|---|---:|---|
|1|−4|2번째 LOT|
|2|−6|3번째 LOT|
|3|−8|4번째 LOT|
|4|−10|5번째 LOT|
|5|−12|6번째 LOT|
|6|−14|7번째 LOT|
|7|−16|8번째 LOT|
|8|−18|9번째 LOT|
|9|−20|10번째 LOT|
|10|−22|11번째 LOT|
|11|−24|12번째 LOT|
|12|−26|기존 최대 12 LOT이면 추가매수 금지|

N=3, m=1, t_buy=1.4라면 -11.2%다. N=3, m=2, t_buy=1이면 -16%다. **최저 매수가 LOT을 매수 앵커로 쓰지 않는다.** Q·VWAP·현재가가 유효하지 않으면 보류한다. 보정 임계값이 -100% 이하이면 `adaptive_pnl_threshold_unreachable`, 목표가 0으로 차단하며 수식을 완화하지 않는다.

보유 0 LOT은 평가PnL이 없으므로 기존 최초 진입 가격별 금액·허용구간을 사용한다. 최초 진입에 가상의 -4% 손실을 요구하지 않는다. 매도 후 제한이 있다면 0 LOT에서도 아래 재매수 상한을 함께 적용한다.

### 최근 실제 매도가 제한과 예비자금

```text
reentry_target = last_sold_price * (1-4*m*b/100)
final_buy_target = min(pnl_target, reentry_target)  # 두 기준이 모두 존재할 때
```

현재가가 두 조건을 모두 충족해야 한다. m=2, 최근 실제 매도가 10,000원이면 재매수 상한은 9,200원이다. 매도 후 첫 실제 매수 체결이 제한을 해제한다. 단순 접수·취소로 해제되지 않으며 SELL 부분 체결도 최신 실제 매도가를 갱신한다.

제한 활성 매수에는 일반 현금 검사에 더해 다음 조건을 적용한다.

```text
주문가능 현금 >= 이번 매수 예산
                 + 보유 각 종목의 추가 2 LOT 예비 예산
                 + 계좌 총 평가자산*0.10
```

재진입 종목을 포함하며 최대 LOT·투자 한도를 초과하는 가상 슬롯은 제외한다. 현금·자산·LOT 근거를 확인하지 못하면 보류한다. 계획은 LOT 예산 전액, 제출 직전은 실제 주문 금액으로 재검사한다. 다른 종목 포함 미해결 매수·접수 결과 불명확 예약이 있으면 재진입은 대기한다. 일반 추가매수에 이 강화된 재진입 예비자금 공식을 새로 적용하지 않는다.

KIS `nrcvb_buy_amt`(없으면 `ord_psbl_cash`)를 주문가능 현금으로 사용한다. 브로커 반영 예약금을 이중 차감하지 않는다. 저장소의 미해결 예약 및 접수 불명확은 별도로 해소돼야 한다. 현금 부족으로 신규 강제매도·교체매도를 추가하지 않았다.

구현: `strategy.adaptive_buy_details/adaptive_reentry_cash_details`, `order_manager._adaptive_submission_guard`, `storage.reserve_order_intent` 및 기존 주문 예약 검사.

## 6. LOT별 매도 목표와 5거래일 Decay

매수 당일은 0일이다. 그 다음 거래일이 정규장 종료 경계를 지나 완료되면 1일씩 증가한다. 주말·휴장일은 증가하지 않는다. D는 각 LOT 최초 체결일 **이후** 완료된 세션 수이며, N은 판단 시 현재 보유 LOT 수다.

```text
decay_pp = N * 0.1 * D / 5
final_profit_target_pct = 3*m*t_sell*c - decay_pp
lot_target_price = 해당 LOT 매수가 * (1 + final_profit_target_pct/100)
```

0.1은 **%p/LOT/5거래일**이다. rate(소수)로는 0.001이다. 변동성 → 추세 → 예수금 배율 → Decay 차감 순서를 지킨다. 5거래일째 몰아서 차감하지 않고 완료된 1세션마다 1/5 반영한다. 누적 Decay를 DB에 더하지 않는다. 예를 들어 N=6, D=20, m=1, s=0, 현금 1억 5천만 원이면 `3*1.5-2.4=2.1%`이며 `(3-2.4)*1.5`로 계산하지 않는다.

| N | D=5 | D=10 | D=20 |
|---:|---:|---:|---:|
|1|0.1%p|0.2%p|0.4%p|
|3|0.3%p|0.6%p|1.2%p|
|6|0.6%p|1.2%p|2.4%p|
|9|0.9%p|1.8%p|3.6%p|
|12|1.2%p|2.4%p|4.8%p|

예: N=6, D=20, m=1, s=0이면 최종 3−2.4=0.6%, 매수가 10,000원의 원 목표는 10,060원이다. LOT 추가로 N=9가 되면 같은 기존 LOT 전체 기간에 3.6%p가 소급돼 최종 -0.6%가 된다. N 감소 시 목표가 다시 높아질 수 있다. 음수 목표를 허용하지만 목표가격 0 이하·비유한 값은 주문하지 않는다.

구현: `lot_manager.age_weeks`는 Adaptive 활성 시 D/5를 반환한다(호환 필드명 유지). `age_decay_rate_for`는 N*0.001, `effective_target_profit_rate/update_lot_target_metadata/recalculate_symbol_targets`가 재계산한다. 다른 비활성 과거 전략의 달력일 계산은 유지한다.

### 실제 매도 선택 순서

`strategy._adaptive_sell_candidate`가 각 LOT의 상태와 목표를 검사한다. 별도 심층 손실회복 조건을 충족한 LOT은 회복 후보군, 나머지는 목표 도달 여부에 따라 비음수 목표 수익실현 후보군·음수 목표 Decay 후보군으로 나눈다. 선택 우선순위는 **일반 수익실현 → 별도 손실회복 → 음수 Decay**다. 같은 후보군의 기존 LOT 정렬·고노출 부분 매도 규칙은 유지한다. 한 루프에 임의로 전 LOT을 청산하지 않는다.

심층 손실회복은 완료 종가로 -40% 상태를 관찰하고 저점·관찰횟수를 관리한다. 최초 요구 반등 15%가 최대 60일 경과에 따라 줄며 기한 도달 시 회복 매도 경로가 있다. **이번 거래일 변경은 Adaptive LOT 목표 Decay에 적용하며 기존 심층 손실회복의 경과 달력일 정책은 바꾸지 않았다.** 일반 -30% 종목 검토 차단은 무조건 시장가 손절이라는 뜻이 아니다.

매도 목표는 호가 단위 올림, 매수 상한은 내림이다. 프로젝트 기존 호가 사다리(1천/5천/1만/5만/10만/50만원 경계)를 그대로 사용한다. 이 사다리를 현재 거래소 전체 상품 호가 규칙과 완전히 일치한다고 검증한 것은 아니다. 목표 도달 일반·Decay 매도 요청은 오래된 낮은 목표를 그대로 내지 않고 확인된 현재가를 사용한다. 깊은 손실회복 주문의 기존 가격 경로는 유지한다. 실제 주문가격·수량은 `OrderManager.build_request`와 제출 가드가 최종 검사한다.

## 7. 판단 및 주문 차단 순서

1. 메인 루프가 런타임 일시정지·시간대·종목 상태·잔고/체결 동기화·가격 표본·API 상태를 확인한다. 가격은 기존 5회·0.5초 표본, 표본 변동 1% 제한 설정을 유지한다.
2. `PositionManager`가 최신 LOT 수량·원가·평가손익·검토 상태를 갱신한다. 거래일 근거와 5세션 점수를 확인한다. 달력 부족 시 자동 주문 판단을 보류한다.
3. SYNC_REQUIRED/RISK_BLOCKED는 거래를 막는다. 기존 매도 후보를 우선 확인한다. 매도가 없으면 계좌·종목 매수 위험 검사를 통과해야 한다.
4. 최초/추가/재매수 가격 조건, 종목 제외·검토·매수 허용·최대 LOT·종목 한도·현금·재진입 예비자금을 확인한다.
5. 포트폴리오 한도, 신규 진입 일별 한도, 매수 체결 후 600초 쿨다운, 주문 요청 10초 간격, 종목의 기존 미해결 주문과 상충 여부를 확인한다.
6. 주문 생성 후 DB 예약 트랜잭션과 제출 직전 가드가 저장 LOT·상태·점수·현재 현금·재진입 예산을 다시 확인한다. 접수 실패/거절/체결/부분 체결은 결과에 따라 분리한다.

현재 설정의 계좌 위험 값: 일일 손실 -1.5%, 전체 손실 -20%, 최소 주문가능 현금 30,000원, 검토 종목 최대 60, API 연속 오류 5회, 최대 활성 종목 300·전체 LOT 3,000·투자 원가 2억원. 신규 최초 진입 하루 최대 300건·총 3천만원이다. 이는 위험 검사 조건이지 모든 손실 도달 시 전 종목을 자동 청산한다는 약속이 아니다. 활성 설정을 이번에 변경하지 않았다.

## 8. LOT 금액·수량·상태

`lot_sizing_mode=cycle_locked_by_entry_price`에서 사이클 최초 실제 매수 체결 가격 구간으로 LOT 예산과 종목 한도를 잠근다. 현재 가격이 구간을 넘어도 같은 사이클의 단위를 임의로 바꾸지 않는다. 기본 최대 12 LOT이다.

| 진입 가격(원) | LOT 예산(원) | 종목 한도(원) |
|---|---:|---:|
|0~300|750|9,000|
|301~1,000|2,250|27,000|
|1,001~3,000|7,500|90,000|
|3,001~10,000|22,500|270,000|
|10,001~30,000|75,000|900,000|
|30,001~100,000|225,000|2,700,000|
|100,001~300,000|750,000|9,000,000|
|300,001~1,000,000|2,250,000|27,000,000|
|1,000,001~3,000,000|7,500,000|90,000,000|

예산/지정가로 정수 수량을 산출한다. 1주 미만이면 주문하지 않는다. 같은 실제 매수 주문의 부분 체결은 한 LOT에 병합해 최초 체결시각과 정확한 누적 체결금액을 보존한다. 매도 부분 체결 후 잔여 수량이 있으면 그 LOT은 N에 포함한다. 실제 체결 반영 시 잔여 VWAP·N·점수·목표를 다시 계산한다. 달력이 없더라도 실제 수량을 잃지 않고 목표를 비활성 상태로 두며 다음 판단에서 보류한다.

상태에는 NEVER_BOUGHT, HOLDING, WAIT_REENTRY, REVIEW_REQUIRED, RISK_BLOCKED, SYNC_REQUIRED, TRADE_STOPPED_AFTER_EXIT 등이 있다. 종목 제외 후 전량 청산 시 재진입을 금지하는 기존 경로를 유지한다. 부분 체결로 임의의 신규 사이클을 만들지 않는다.

`storage.StateStore.load_positions`는 과거 `actual_fill_events`가 없는 종목을 실제 fills에서 복원한다. 이력 존재 시 기존 영속 기록을 사용한다. 이번 변경은 새 DB 열이나 운영 DB 마이그레이션을 실행하지 않는다. 기존 누락 체결·잔고 불일치는 기존 동기화 차단과 복구 경로를 유지한다. 체결 저널과 모든 LOT 반영이 하나의 트랜잭션으로 묶이지 않는 기존 구간까지 새로 개편하지 않았다.

## 9. 예외·주문 수명·시간외

접수 결과가 불명확한 주문은 미접수로 단정해 재전송하지 않고 예약·조회 복구를 유지한다. 취소 거절도 예약 해제 근거가 아니다. 기존 30초 지정가 미체결 처리, 최근 체결 조회, 중복 체결 ID 검증을 유지한다. 봇의 DB 단일 실행 잠금도 유지한다.

시간외는 `extended_hours` 설정과 `market_session.SessionMarketData`의 휴장·종목·거래소별 가격 및 지원 여부 검증을 통과해야 한다. 기본 비활성 기능을 이번에 활성화하지 않았다. 가격 근거가 없는 거래소·시장가는 새 정책의 매수 상한을 우회하지 못한다. 시간외 체결도 KST 실제 날짜로 추세에 포함되며 완료 정규장 Decay 경계는 2절과 같다.

## 11. 수식 변경의 부수 효과와 검증 범위

10,000원 10주를 보유하고 9,600원 10주를 추가매수하면 VWAP은 9,800원, N=2·m=1·s=1일 때 다음 목표는 9,212원이다. 같은 9,600원에서 즉시 다음 매수 조건이 충족되지 않는다. 하지만 수량 비중·매도 LOT 구성에 따라 VWAP이 달라지므로 모든 상황에 고정된 가격 간격을 보장하지 않는다. 최근 매도 제한은 가격이 그대로인 재매수를 추가로 막는다. 기존 주문 간격·쿨다운도 유지한다.

큰 N·m·점수에서 도달 불가능한 기준이 생긴다. 예를 들어 N=12·m=2.5·s=12이면 -26*2.5*3.2=-208%다. 이 경우 최대 LOT 제한도 적용된다. N=6에서도 -14*2.5*3.2=-112%이므로 수학적으로 차단될 수 있다. 실거래 발생 빈도나 기대수익은 이번 작업에서 측정하지 않았다. 상한 도입·배율 감쇠는 전략 변경이므로 자동 적용하지 않는다.

테스트는 임시 DB·가짜 브로커·명시적인 가짜 거래일을 사용한다. 전체 회귀 테스트 **1,323개 통과**이며 새 핵심 정책 검증 13개를 포함한다. 마지막 로그·화면 수정은 관련 테스트를 추가 실행했다. 실제 휴장일 API의 계좌 인증·날짜 범위·특수 장 종료시각·운영 DB 원본 체결의 완전성은 실거래 연결 검증과 별개다. 변경 파일·운영 파일 해시는 [변경 보고서](POLICY_V2_CHANGE_REPORT.md)에 기록한다. 테스트용 평일 달력을 실제 KRX 일정 검증 결과로 해석하지 않는다.
